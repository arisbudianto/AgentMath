# M04 — Pengendali proses penilaian

Pengajar membuka **Asesmen → Proses penilaian · antrean dan riwayat**, atau membuat proses dari detail jawaban. Pilih jawaban terkini dan centang konfirmasi. Sistem memeriksa rubrik yang disahkan, kesesuaian sumber soal, dan konfirmasi transkripsi foto. Antrean berjalan di worker, bukan dalam request web.

## Cakupan modul

M04 menyediakan penyimpanan proses, snapshot input/configuration, antrean database, urutan tahap, validasi output, checkpoint, riwayat percobaan/peristiwa, pembatalan dan pemulihan. Pemeriksaan awal (`preflight`) benar-benar dijalankan: teks dan rubrik divalidasi dengan validator M02/M03. Setelah itu proses menjadi `awaiting_agent` pada Marker A. **M05 belum diimplementasikan**: tidak ada penilaian, arbitrase, confidence, skor simulasi atau persetujuan nilai pada M04. Status menunggu berbeda dari gagal; kegagalan tidak menjadi nilai nol.

`GradingStages` adalah titik integrasi tahap berikutnya: `supports`, `execute`, `validate`. Urutan kontrak: preflight, Marker A, Marker B, arbitrase, confidence. Konteks Marker A/B tidak menerima hasil Marker lain. Tahap arbitrase/confidence menerima checkpoint berhasil sebelumnya. Pemicu arbitrase per kriteria, pemilihan hasil Marker dan validasi skor/bukti/confidence merupakan pekerjaan M05; adapter produksi saat ini menolak menjalankan tahap-tahap tersebut. Pengujian kontrak menggunakan adapter uji, bukan implementasi penilaian produksi.

## Data dan konsistensi

- `grading_runs`: revisi jawaban, transkripsi confirmed (foto), versi rubrik, pemilik/pembuat, UUID request, snapshot teks/soal/rubrik, hash input dan snapshot konfigurasi tanpa API key. Tidak menaruh nama/kode peserta dalam input agent.
- `grading_attempts`: tahap, nomor percobaan, lease token, waktu, hasil tervalidasi atau kode gagal. Hasil final percobaan terkunci melalui model; gagal tidak menyimpan output parsial/provider error.
- `grading_events`: peristiwa append-only, tahap, aktor dan waktu.
- `agentmath_jobs`: antrean Laravel terpisah; payload hanya ID proses/generation. `failed_jobs` menampung kegagalan infrastruktur worker; seluruh tabel berada di database privat.
- Run/snapshot, antrean dan checkpoint ditulis dalam transaksi database yang sama melalui koneksi `grading`, bukan dispatch-after-commit. Koneksi ini selalu database default yang sama, tabel `agentmath_jobs`, queue `grading`, `retry_after=120`; `QUEUE_CONNECTION=sync` lama tidak membuat grading berjalan sinkron.
- Kunci baris asesmen lalu proses menserialkan pembuatan, pemrosesan dan kendali. Hanya satu proses aktif per jawaban. UUID sama untuk target/pembuat sama mengembalikan proses yang sama, tanpa antrean ganda. Buat ulang dengan UUID baru setelah proses lama dibatalkan/terminal.
- Generation dan lease token menolak job lama, duplicate delivery dan hasil yang kembali setelah cancel/retry. Lease 120 detik, timeout job 60 detik, satu percobaan Laravel per delivery. Output yang tiba setelah lease berakhir ditolak.
- Keberhasilan tahap disimpan sebelum tahap berikutnya dijadwalkan secara atomik. Retry hanya tahap belum berhasil, maksimal tiga percobaan per tahap; tidak mengulang checkpoint sukses. Tidak ada retry API otomatis atau biaya AI pada M04.
- Pemeriksaan sebelum/sesudah tahap memastikan jawaban, transkripsi, sumber soal dan versi rubrik masih terkini serta pemilik masih pengajar aktif. Perubahan menjadi `stale`, hasil lama hanya riwayat. Snapshot tidak ditimpa.
- Perubahan konfigurasi tidak mengubah snapshot run lama. M05 harus memvalidasi kemampuan/configuration snapshot sebelum panggilan nyata; proses dibuat saat AI nonaktif tidak boleh diam-diam menggunakan konfigurasi baru. Buat proses baru setelah konfigurasi dipilih.

## Worker shared hosting

Jalankan dari root aplikasi menggunakan PHP CLI yang benar:

```bash
php artisan agentmath:work
```

Command mengambil lock cache 180 detik, menandai lease kedaluwarsa sebagai `failed/worker_interrupted`, lalu `queue:work grading --queue=grading --stop-when-empty --max-time=45 --max-jobs=100 --sleep=1 --tries=1 --timeout=60`. Worker berhenti saat kosong. Max-time diperiksa antar job, jadi satu job yang sedang berjalan dapat menambah durasi sampai batas timeout. Heartbeat terakhir selesai disimpan selama tujuh hari dan tampil di halaman pengajar. Heartbeat adalah tanda worker menyelesaikan tick, bukan jaminan semua proses sukses.

Untuk cPanel gunakan cron setiap menit dengan executable/path absolut dan lock OS `flock`, log privat terbatas. Jangan menjalankan worker web atau mengekspos endpoint pemicu publik. Deployment harus mengambil lock OS yang sama sebelum maintenance/rsync sehingga worker aktif selesai lebih dahulu. Hindari memuat kode versi berbeda dalam worker yang sama.

### Pemulihan

- Worker terputus: tick berikutnya menandai lease expired sebagai gagal. Pengajar dapat **Lanjutkan / pulihkan antrean** setelah memeriksa kode kegagalan. Tidak ada retry berbayar otomatis.
- Antrean tidak bergerak/kehilangan delivery: proses queued berumur lebih dari dua menit boleh dijadwalkan ulang; generation lama diabaikan. Periksa heartbeat dan cron dahulu.
- Proses running dengan lease aktif tidak dapat diambil alih. Pembatalan tetap tersedia dan membuat hasil worker lama diabaikan.
- Tiga percobaan gagal: periksa penyebab, lalu buat proses baru bila memang perlu; riwayat lama tetap ada.
- `awaiting_agent`: menunggu implementasi M05, bukan kegagalan. Tidak ada tombol retry yang menjanjikan penilaian sebelum agent tersedia.
- Perubahan dasar: batalkan proses aktif lama, lengkapi rubrik/transkripsi terbaru dan buat proses baru.

Referensi: [Laravel 13 queues](https://laravel.com/framework/docs/13.x/queues). Penerapan ini memakai database queue dengan transaksi dan generation/lease aplikasi untuk mencegah hasil ganda.

## Verifikasi

SQLite dan CI MariaDB: replay, snapshot tanpa key, antrean database meski default sync, worker nyata, gating foto/rubrik, stale source, rollback antrean atomik, akses pemilik, akun nonaktif, output invalid/failure, retry/batas tiga, pemulihan lease, delivery lama, pembatalan saat eksekusi, urutan kontrak dan isolasi Marker. Browser lokal: buat antrean, jalankan worker CLI, lihat checkpoint/peristiwa dan batalkan tanpa menghapus riwayat. Tidak menguji kualitas penilaian AI karena adapter M05 belum tersedia.
