# M02 — Pedoman, rubrik dan pengesahan

## Alur pengajar

Asesmen → Rubrik per soal → kelola pedoman dan rubrik. Buat draf manual atau, jika konfigurasi AI aktif, draf AI. Periksa aturan/kutipan, bukti yang diperlukan, aturan skor nol/parsial/penuh, skor maksimum dan kebijakan. Simpan, lalu centang konfirmasi pengesahan. Versi disahkan terkunci. Perubahan dilakukan melalui draf versi baru, dengan rujukan ke versi asal.

Pedoman dalam M02 berasal dari teks pedoman soal dan petunjuk asesmen yang sudah tersedia di M01; belum ada unggah dokumen pedoman. Setiap aturan memiliki rule_id, sumber, kutipan persis, dan ringkasan. Setiap kriteria memiliki criterion_id, deskripsi, bukti yang diperlukan, kebijakan skor, max_score, dan rujukan rule_id. Batas 20 aturan dan 20 kriteria per versi.

Sumber versi menyimpan salinan soal, kunci, pedoman, petunjuk asesmen dan skor maksimum beserta hash. Perubahan salah satunya membuat versi lama tidak sesuai dengan dasar terkini. Versi tersebut tetap tersimpan sebagai riwayat. Nomor soal dan judul asesmen tidak memengaruhi hash karena tidak mengubah substansi penilaian.

Rubrik berlaku adalah versi disahkan terbaru yang cocok dengan dasar terkini. Draf baru tidak otomatis menggantikan versi disahkan. Kriteria dan aturan versi disahkan tidak dapat ditimpa melalui aplikasi. Kunci asing melindungi hubungan versi, pengguna dan soal dari penghapusan induk.

## Validasi dan konflik

- Kutipan wajib ditemukan persis dalam satu sumber yang disebut.
- rule_id dan criterion_id harus unik; rujukan aturan harus tersedia dan tidak berulang dalam satu kriteria.
- Skor kriteria >0, ≤10.000 dan maksimal dua desimal. Jumlah dibandingkan dalam satuan perseratus dengan skor maksimum soal.
- Penyimpanan memakai nomor revisi untuk menolak tab lama; pengesahan hanya memakai draf tersimpan, bukan field tambahan dari request.
- Pengesahan memerlukan konfirmasi eksplisit dan memeriksa ulang sumber serta isi rubrik di dalam transaksi.
- Versi ditetapkan dengan penguncian baris soal/asesmen. UUID pembuatan dan cache lock mencegah pengiriman ulang formulir yang sama membuat versi/panggilan AI ganda.
- Pembuatan draf dibatasi tiga permintaan per menit per pengguna. Kesalahan validasi tidak mengubah versi terakhir yang tersimpan.
- Semua rute mewarisi pembatasan pengajar aktif dan kepemilikan asesmen. ID soal/rubrik dicari melalui induknya. Admin tidak memperoleh akses isi.

## Dua peran AI

Adapter OpenAI Responses API menjalankan A1 Guideline Extractor lalu A2 Rubric Creator, dengan structured JSON schema strict. Keluaran tetap divalidasi server: kutipan A1 diperiksa sebelum A2 dipanggil, lalu rujukan/skor A2 diperiksa sebelum draf disimpan. AI tidak dapat mengesahkan.

Permintaan hanya memuat soal, kunci, teks pedoman/petunjuk dan aturan hasil A1. Tidak ada daftar peserta, nama akun, owner_id, assessment_id atau jawaban siswa. Teks sumber ditandai sebagai data tidak tepercaya di dalam prompt. Pengajar perlu memastikan teks soal/pedoman tidak memuat identitas langsung siswa. `store=false`; tidak ada tools atau akses pencarian. Endpoint tetap HTTPS api.openai.com; redirect dan retry otomatis dinonaktifkan.

Konfigurasi server: AI_ENABLED, AI_PROVIDER=openai, AI_MODEL, AI_API_KEY, AI_MAX_OUTPUT_TOKENS (default 4000, dibatasi 1000–8000 per panggilan). Model harus mendukung Responses structured outputs. Tidak ada model atau API key bawaan. AI dinonaktifkan jika konfigurasi belum lengkap; draf manual tetap berfungsi. Batas waktu setiap panggilan 40 detik (koneksi 10 detik), maksimal dua panggilan sinkron pada M02. Worker/antrean untuk pemrosesan lebih luas tetap M04.

Status incomplete, refusal, kegagalan HTTP, JSON rusak, dan keluaran tidak valid ditolak. Tidak ada nilai nol atau persetujuan otomatis akibat kegagalan. Isi error provider/kunci tidak ditampilkan atau dicatat. Draf AI yang valid menyimpan penyedia, model, versi prompt, response_id serta pemakaian A1/A2; perubahan manual tidak menghapus provenance draf awal.

Implementasi API mengikuti [Structured model outputs — official OpenAI documentation](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses). Kualitas pedagogis rubrik belum dibuktikan oleh keberhasilan tes teknis dan tetap memerlukan evaluasi M08.

## Pengujian dan deployment

35 tes / 274 assertions lokal pada PHP 8.5.11, termasuk M00–M01. AI diuji dengan respons HTTP simulasi, bukan panggilan berbayar ke layanan produksi. Browser lokal memverifikasi pembuatan, penambahan/penghapusan baris editor, penyuntingan, penyimpanan dan pengesahan. Waktu pengesahan ditampilkan Asia/Jakarta secara default (APP_DISPLAY_TIMEZONE); timestamp database tetap mengikuti konfigurasi aplikasi.

Migrasi hanya menambah rubric_versions, tanpa mengubah tabel/data M00–M01. Urutan deployment: test → GitHub → CI PHP 8.3/8.4 SQLite/MariaDB → backup → preview migrasi → cPanel → migrate/cache → smoke. Pertahankan .env/APP_KEY, storage dan konfigurasi web.

Rollback kode ke M01 tidak memerlukan penghapusan tabel rubrik. Jangan migrate:rollback pada produksi karena akan menghapus riwayat. Pengujian API nyata menunggu konfigurasi server yang sah; jangan menyimpan kredensial pada GitHub atau chat.
