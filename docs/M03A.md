# M03A — Transkripsi foto dan konfirmasi pengajar

Pengajar membuka **Asesmen → Kelola jawaban → jawaban foto → Buka transkripsi dan status konfirmasi**. Foto privat dan teks tampil berdampingan. Ketik salinan apa adanya, simpan draf, koreksi bila perlu, lalu bandingkan draf tersimpan dengan foto dan centang pemeriksaan sebelum konfirmasi. Konfirmasi tidak memberikan nilai.

## Data dan keputusan

- Tabel tambahan `answer_transcriptions` terikat pada revisi foto asli. Setiap penyimpanan dan konfirmasi menambah versi, aktor, waktu, alasan dan kunci permintaan; versi lama tidak ditimpa melalui model. Foto/revisi jawaban M03 tetap utuh.
- Draf AI tidak otomatis terkonfirmasi. Bagian meragukan mencatat lokasi/deskripsi dan dipertahankan saat koreksi manual. Penanda `[tidak terbaca]`, `[ragu...]`, `[illegible...]`, `[unclear...]` menghalangi konfirmasi sampai diselesaikan.
- Konfirmasi hanya menerima teks yang persis sama dengan draf tersimpan dan memerlukan checkbox pemeriksaan. Koreksi harus disimpan sebagai draf dahulu. Koreksi setelah konfirmasi membuat teks kembali berstatus draf.
- Perubahan bersamaan dicegah dengan versi yang diharapkan, transaksi dan kunci baris asesmen/jawaban. Permintaan ulang dengan UUID sama dan isi sama tidak menggandakan versi. Permintaan AI memakai kunci cache 90 detik dan pemeriksaan replay sebelum jaringan; tidak ada retry jaringan otomatis.
- Foto lama hanya dapat dilihat beserta riwayat transkripsinya. Foto baru memerlukan transkripsi/konfirmasi baru. Hasil AI yang selesai setelah jawaban diganti ditolak.
- `TranscriptionWorkflow::readyText()` adalah pintu masuk modul penilaian berikutnya: hanya revisi jawaban terkini dengan hash sumber soal yang masih cocok; foto memerlukan versi transkripsi terbaru berstatus confirmed. Tidak kembali ke konfirmasi lama bila ada draf koreksi baru.
- Semua rute memerlukan akun pengajar aktif dan kepemilikan asesmen; admin tidak melewati kepemilikan. Respons tetap privat/no-store. Teks/hasil AI ditampilkan dengan escaping Blade.

## Bantuan AI opsional

Memerlukan `AI_ENABLED=true`, **`AI_TRANSCRIPTION_ENABLED=true`**, provider OpenAI, API key dan model yang mendukung gambar serta JSON schema. Default keduanya false; pengembangan/deployment tidak mengaktifkannya. Pengajar wajib memastikan foto bebas identitas pribadi dan menyetujui pengiriman sebelum permintaan.

Adapter mengirim byte foto via base64 ke endpoint tetap HTTPS Responses API, `store=false`, gambar detail high, output JSON schema ketat, timeout 45 detik, tanpa redirect/retry otomatis. Hash byte foto diverifikasi sebelum kirim. Tidak mengirim kunci, pedoman, teks soal, kode peserta, nama akun, atau URL file privat sebagai konteks tambahan. Foto asli masih dapat mengandung informasi visual/metadata: pengajar harus memeriksanya sebelum pengiriman; aplikasi belum melakukan redaksi otomatis atau menghapus EXIF. Jangan unggah foto beridentitas pribadi untuk AI.

Prompt melarang penilaian, penyelesaian soal dan pembetulan jawaban siswa. Output wajib teks dan daftar keraguan yang tervalidasi; refusal, output tidak lengkap/rusak, foto berubah dan kegagalan provider menghasilkan pesan umum tanpa membocorkan body/key. Tidak ada permintaan live berbayar pada pengujian ini; kemampuan baca tulisan tangan dan matematika belum dievaluasi secara empiris. Transkripsi manual berfungsi tanpa AI.

Referensi implementasi: [OpenAI image inputs](https://developers.openai.com/api/docs/guides/images-vision), [Structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Adaptasi aplikasi selalu memerlukan konfirmasi pengajar.

## Validasi

Pengujian otomatis mencakup draf/konfirmasi, angka nol dan whitespace, replay, riwayat terkunci, tab stale, foto/dasar soal berubah, akun lain/nonaktif, checkbox, permintaan AI simulasi tanpa konteks kunci/identitas, keraguan, foto rusak, refusal/output tidak lengkap/JSON invalid, dan perubahan jawaban selama permintaan AI. Browser lokal memakai foto sintetis, tanpa data siswa. Tidak mencakup akurasi OCR layanan nyata atau login manual produksi.
