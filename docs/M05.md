# M05 — Penilaian dan arbitrase

Guru membuka Asesmen → Proses penilaian, memilih jawaban terkini dan mengonfirmasi pengiriman. Jawaban harus memakai rubrik disahkan; foto harus memiliki transkripsi terkini yang dikonfirmasi. Worker cron menjalankan preflight, dua Marker independen, arbitrase bila perlu, lalu Confidence Estimator. Hasil berupa **usulan**, bukan nilai akhir dan tidak ditampilkan pada portal siswa. Koreksi/persetujuan nilai merupakan M06.

## Kontrak hasil

Marker A/B menggunakan request stateless terpisah dengan dasar soal/rubrik/teks yang sama, tanpa hasil satu sama lain, ID akun atau kode peserta. Provider/model dipilih server, saat ini Dinoiki gpt-5-mini. Teks jawaban dan dasar penilaian dikirim ke penyedia tersebut; guru harus memastikan tidak memuat identitas pribadi. Seluruh konten sumber dan hasil agent diperlakukan sebagai data, bukan instruksi sistem.

Setiap Marker harus memberi tepat satu hasil untuk setiap criterion_id: skor angka maksimal dua desimal dalam batas kriteria, kutipan persis yang ditemukan dalam teks jawaban, ringkasan alasan, dan rule_ids dari kriteria tersebut. Bukti kosong wajib dinyatakan missing_evidence, dengan skor nol; skor nol bukan pengganti error. Server menormalisasi urutan kriteria, menghitung total dalam satuan perseratus dan menolak keluaran tambahan, ID duplikat/tidak dikenal, skor di luar batas serta kutipan karangan. Pemeriksaan kutipan membuktikan keberadaan teks, bukan ketepatan interpretasi matematikanya.

Selisih skor pada satu kriteria memicu Arbitrator, termasuk ketika total Marker sama. Arbitrator memilih **satu hasil Marker secara utuh**, tanpa rata-rata, gabungan atau skor baru, dan memberi alasan serta rujukan untuk setiap kriteria berbeda. Bila semua skor kriteria sama, checkpoint arbitrase mencatat dilewati dan memilih Marker A secara deterministik; tidak ada panggilan Arbitrator. Perbedaan alasan/bukti dengan skor identik tetap tersedia bagi Confidence Estimator dan guru.

Confidence Estimator menerima seluruh dasar dan hasil sebelumnya, tanpa hak mengubah skor. Label hanya High/Low disertai alasan; Low wajib memiliki kekhawatiran berkriteria. Label bukan probabilitas terkalibrasi. Bukti hilang pada salah satu Marker memaksa label efektif Low meskipun estimator memberi High; keluaran asli tetap tercatat. Selisih Marker, bukti hilang dan label Low diberi penanda pemeriksaan. **Semua hasil, termasuk High, wajib ditinjau guru.**

Halaman proses menampilkan perbandingan skor A/B, pilihan Marker, bukti, alasan, arbitrase dan label efektif. Usulan hanya ditampilkan setelah seluruh tahap berhasil. Jika dasar jawaban/rubrik berubah, usulan ditandai historis. Output antara tetap berada di riwayat privat guru; tidak menjadi nilai final.

## Konsistensi dan kegagalan

Snapshot konfigurasi baru memakai pipeline m05_v1. Provider, model, flag aktif dan batas output harus sama persis dengan konfigurasi server sebelum/selepas panggilan. Key tetap hanya server. Proses M04 lama tidak otomatis dipromosikan menjadi penilaian berbayar; batalkan dan buat proses baru. Perubahan konfigurasi menghasilkan configuration_changed, tanpa usulan atau penggantian snapshot.

Timeout HTTP 45 detik (connect 10), lebih pendek dari timeout job 60 detik dan lease/retry_after 120 detik. Worker dapat melanjutkan pada tick berikutnya bila batas waktu total tick tercapai. Tidak ada retry HTTP atau fallback model otomatis. Error/refusal/incomplete/body berlebih/JSON salah/kontrak domain salah menghentikan tahap, tanpa menyimpan respons parsial atau detail provider. Retry manual maksimal tiga percobaan per tahap dan tidak mengulang checkpoint sukses. Cancel, stale source, akun nonaktif, lease dan generation M04 tetap berlaku; hasil yang terlambat ditolak.

Tidak ada migrasi baru. Hasil tervalidasi dan metadata prompt/provider/model/token tersimpan dalam grading_attempts yang sudah immutable setelah terminal; metadata tidak menyimpan key atau provider error body. Queue hanya membawa ID/generation. Deployment harus memegang OS lock worker, mempertahankan environment/storage, dan memberi mode 600 pada cache konfigurasi.

## Verifikasi dan batas

Suite mencakup worker database nyata dengan HTTP mock, isolasi Marker, persetujuan skor, arbitrase total sama, pemilihan utuh, schema lokal, batas/desimal skor, rujukan/bukti, label Low, checkpoint palsu, konfigurasi berubah, pembatalan/perubahan sumber saat request, retry dan escaping tampilan. Kontrak M04 diuji dengan adapter preflight-only agar dapat diuji tanpa layanan berbayar. Hasil ini tidak membuktikan akurasi pedagogis; evaluasi manusia dan kalibrasi High/Low tetap cakupan M08.
