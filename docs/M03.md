# M03 — Penerimaan dan revisi jawaban

## Alur pengajar

Asesmen → Kelola jawaban. Tersedia ketikan, impor CSV, dan satu foto per jawaban per soal. Peserta harus berasal dari kelas asesmen dan soal harus berasal dari asesmen itu. Satu pasangan peserta–soal memiliki satu jawaban logis, dengan riwayat revisi yang tidak ditimpa.

Penerimaan tidak menjalankan AI, memberikan skor, atau mengesahkan nilai. Foto belum ditranskripsikan; pembacaan serta konfirmasi transkripsi pengajar tetap M03A. Teks tersimpan belum dinilai.

## Ketikan dan revisi

- Teks UTF-8, 1–20.000 karakter, tidak boleh hanya spasi atau mengandung NUL. Jawaban `0` diterima. Spasi awal/akhir dipertahankan; CRLF/CR dinormalisasi menjadi LF.
- Setiap revisi menyimpan versi, pembuat, alasan, isi atau rujukan foto privat, hash isi, salinan kode peserta dan dasar soal (termasuk kunci/pedoman/petunjuk/skor maksimum) serta source_hash.
- Membuat jawaban lagi untuk pasangan yang sama ditolak; gunakan revisi dengan alasan. Isi yang sama dengan revisi terakhir juga ditolak.
- Formulir awal memakai UUID; retry permintaan sama tidak menggandakan jawaban. UUID dengan target/isi berbeda ditolak.
- Revisi membutuhkan expected_version yang cocok. Revisi dari tab lama ditolak. Baris riwayat tidak dapat disunting/dihapus melalui model.
- Penggantian kelas asesmen diblokir setelah jawaban ada. Penggantian kode peserta/soal tetap tidak menimpa snapshot lama. Dasar soal yang berubah ditandai sebelum penilaian pada modul lanjutan.

## CSV

Header harus tepat tiga kolom: `participant_code,question_number,answer_text`. Urutan dapat diubah, pemisah koma/titik koma, UTF-8 dengan/tanpa BOM. Kolom dengan koma/baris baru harus diapit petik ganda, petik di dalamnya ditulis `""`. Ekstensi .csv, maksimal 2 MiB dan 500 record data. Nomor soal berisi 1–4 digit; kode peserta dinormalisasi kapital. Template hanya berisi header dan contoh sintetis, bukan data siswa.

CSV diperiksa sintaks, encoding, jumlah kolom, peserta, soal, jawaban kosong/panjang, pasangan berulang dalam file, dan jawaban yang sudah ada. Kesamaan isi di antara peserta berbeda tidak dianggap duplikasi atau bukti plagiarisme. Formula/string instruksi tetap menjadi data teks, tidak dieksekusi.

Pratinjau disimpan privat pada database selama satu jam, tanpa membuat jawaban. Konfirmasi memerlukan centang pengajar. Server membaca payload pratinjau tersimpan, memeriksa ulang identitas target dan hash dasar soal, lalu memasukkan seluruh batch dalam satu transaksi. Perubahan kode/kelas/nomor/isi soal atau munculnya jawaban baru menahan batch. Tidak ada impor sebagian atau penimpaan jawaban lama. Konfirmasi berulang tidak menggandakan hasil. Revisi awal yang diimpor menyimpan asal batch CSV.

Payload pratinjau dikosongkan setelah sukses atau pembatalan. Setelah kedaluwarsa payload tidak ditampilkan dan konfirmasi ditolak. Pembuatan pratinjau baru juga membersihkan payload pratinjau lama yang kedaluwarsa. Perintah `php artisan agentmath:purge-imports` tersedia untuk pembersihan tanpa menunggu impor baru; cron terjadwal belum dipasang. Metadata batch yang tidak mengandung jawaban tetap disimpan untuk jejak asal.

## Foto privat

JPG/JPEG atau PNG, maksimal 5 MiB, 6000 piksel per sisi dan 20 megapiksel. Validasi unggahan, ukuran, header gambar/dimensi, dan kecocokan ekstensi. Nama file asli tidak disimpan. Satu unggahan menghasilkan satu foto untuk satu peserta–soal; tidak ada pemisahan banyak soal/lembar otomatis.

Disk `answers` memakai storage/app/private/answers, UUID acak, visibility private, file mode 600/direktori 700, tanpa public link atau serve URL otomatis. Disk local generik juga tidak menyediakan serve route otomatis. Foto hanya dikirim melalui controller yang memeriksa peran aktif, kepemilikan asesmen, ID jawaban dan revisinya. Respons memakai MIME gambar, no-store/private, nosniff dan CSP sandbox. Foto tidak dikirim ke AI.

Revisi foto tidak menimpa file lama. Bila penulisan/transaction gagal, file baru dibersihkan dan jawaban tidak dianggap tersimpan. File foto asli tetap privat termasuk metadata gambarnya; hindari identitas siswa pada foto. Tidak ada penghapusan riwayat atau file lama pada M03.

Runtime web perlu file_uploads aktif, folder upload sementara yang dapat ditulis, upload_max_filesize ≥5M (disarankan 6M), post_max_size ≥8M. Pengujian browser lokal memakai folder sementara khusus dalam .tools (diabaikan Git), upload 6M dan post 8M.

## Akses dan pengujian

Semua rute memerlukan pengajar aktif pemilik asesmen; admin tidak mendapat akses isi. Relasi anak selalu dicari melalui induk. Field owner/pembuat/asal/konten snapshot dari klien tidak dipakai untuk memindahkan data. Foto tidak mengungkap path disk dan seluruh teks dirender dengan escaping Blade.

55 tes / 437 assertions lokal PHP 8.5.11 PASS, termasuk M00–M02, isolasi akun, foto privat dan sesi nonaktif, CSV malformed/UTF-8/BOM/multiline/duplikasi, expiry, konfirmasi ulang, perubahan saat pratinjau, kegagalan penyimpanan foto dan rollback kegagalan di tengah batch. Browser lokal memverifikasi ketikan, pratinjau/konfirmasi CSV, foto yang dapat ditampilkan, dan revisi dengan alasan. Upgrade M00→M01→M02→M03 mempertahankan data sebelumnya.

## Deployment dan pemulihan

Migrasi menambah answer_import_batches, answers, answer_revisions. Tidak ada perubahan tabel/data lama. Ikuti test → GitHub → CI PHP 8.3/8.4 SQLite/MariaDB → backup → SQL preview → cPanel migration/cache → smoke. Pertahankan .env/APP_KEY, storage dan konfigurasi PHP web; periksa batas unggahan web.

Rollback kode ke M02 tidak memerlukan penghapusan tabel atau foto. Jangan migrate:rollback pada produksi karena menghapus semua jawaban/riwayat/impor. Simpan backup privat dan evaluasi pemulihan database terpisah dari kode.
